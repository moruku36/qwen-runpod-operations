# 用語・エンティティ・検証フェーズ定義書

この文書は「名詞」(用語・フェーズ・ステータス)の台帳である。手順(動詞)は Skills や docs/disciplines/ に置く。
文書にステータスを書く前に、必ずここを読む。

> 優先順位: この辞書と一次記録(`baseline.json`、`docs/development-status-*.md`、CIログ、試行レポート)が食い違った場合は、一次記録を上位の正とし、この辞書を直す。

## 1. 検証フェーズ

| 用語 | ステータス | 根拠(上位ソース) | 書いてよい表現 | 書いてはいけない表現 |
| --- | --- | --- | --- | --- |
| C1 (CPU implementation) | 受入済 (Accepted) | `docs/development-status-2026-10-06.en.md` | 「C1 CPU実装は受入済み」 | 「本番稼働済み」「課金実測で検証済み」(fake provider の結果は運用・課金の証拠ではない) |
| C2 v5 (disabled C2 v5) | 無効化状態で受入済 (Accepted in disabled state) | 同上 | 「無効化されたC2 v5は受入済み」 | 「C2を有効化した」「provider/tunnel を有効化済み」 |
| C3 (live on-demand activation) | 未実行 (Unexecuted) | 同上 | 「C3 live on-demand有効化は未実行である」 | 「稼働済み」「検証完了」「動作確認済み」(推測で書かない) |

C3 の実行には、別途レビューされた有効化計画と費用・権限の承認が必要である。この辞書の記述は承認や開始を意味しない。

## 2. 事実・観測・推測の3区分

| 区分 | 定義 | 書き方 |
| --- | --- | --- |
| 事実(公開資料) | 公式発表・公式ドキュメント・公開リポジトリで裏付けられる内容 | 出典URLまたはファイルを添える |
| 観測(実測値) | 筆者の環境・特定コミット・特定日時に実際に測定・確認した値 | 計測日・対象コミット・環境を添える |
| 推測(未確認) | 公開資料と挙動からの解釈、または未検証の領域 | 「推測」「未確認」と明記する |

実行していないものを「完了」「検証済み」と書かない。未実行は UNEXECUTED と書く。

## 3. 主要エンティティ

| 用語 | 意味 |
| --- | --- |
| Pod | RunPod 上の実行単位。作成・再開・終了は費用と権限を伴うため、文書の公開だけでは実行されない |
| Pod Volume / Network Volume | 前者は使い捨て(既定)。後者(7日間保持等)は既定にしない。`baseline.json` の `default_storage` が正 |
| OWUI | Open WebUI。C1/C2 の契約テストの対象 |
| fake / synthetic | 実provider・実SSH・実課金を使わない検証。運用・課金の証拠にしない |
| 履歴スナップショット | 日付つきの過去記録(例: 2026-10-02 の試行レポート)。現在の状態の根拠にしない |

## 4. 書き方の補足

- README の冒頭ステータスと `docs/development-status-*.md` が食い違った場合は、新しい日付の development-status を優先し、README を直す。
- 日付つきレポートの内容を「現在」として書き換えない。現在の状態は別行で追記する。
