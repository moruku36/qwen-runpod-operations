# メトリクス・計測ソース・日付定義書

> 優先順位: この辞書と一次計測ファイル(`baseline.json`、CIログ、試行レポート等)が食い違った場合は、一次計測ファイルを常に上位の正とする。

## 1. 引用時に必ず添えるもの

数値・所要時間・コスト試算を書くときは、次を添える。添えられない項目は「未確認」と書く。

- 計測日(または確認日)
- 対象コミット(コードやテスト結果の場合)
- 環境(OS、Pythonバージョン、GPU/CPU、リージョン等)
- 区分: 観測(実測)/ 試算(計画値)/ 公開価格(確認日つき)

## 2. 数値の上位ソース

| 数値の種類 | 上位ソース | 区分と注意 |
| --- | --- | --- |
| モデル・ランタイムのピン、サイズ、publisher sha256 | `baseline.json` | publisher 情報であり、ローカルのダウンロード検証ではない(`download_verified: false`) |
| 2時間セッションの費用見積 | `baseline.json` の `estimated_two_hour_cost_usd_excluding_tax` | 試算。支出承認ではない(`spending_approved: false`) |
| GPU公開価格(A100 80GB、A40 48GB) | `README.md` / `docs/runpod-runbook.*` の確認日つき記載 | 2026-10-02 時点。実際の起動画面が優先 |
| 実験の経過時間・GPU稼働・課金 | `docs/trial-report-2026-10-02.*`、`docs/trial-log-2026-10-02.*` | 観測。履歴スナップショット |
| キャッシュ済みA100/27B診断(1リクエスト、context8192、load347.956s) | `README.md` 冒頭 | 観測。1回の診断であり性能比較の結論ではない |
| CPUテスト件数・受入結果 | `docs/development-status-2026-10-06.*` | 受入時点の履歴結果。公開後のCIとは別。CIの現在値はCIログが正 |
| 現在のCI結果 | GitHub Actions のログ | 通過・スキップの区別を保つ(スキップを通過と書かない) |

## 3. 日付と期間のルール

- 暦上の準備期間(例:「約2週間」のような体感期間)と、実測された経過時間・GPU稼働時間・ベンチマーク時間を、混同して合算・分解しない。
- 日付つきレポートの数値は、その日付の観測として引用する。現在の状態として書く場合は、現在の一次記録を確認する。
- 為替・単価は確認日と前提レートを添える。実際の請求額は請求画面の確認が必要で、確認前は「未確認」と書く。
- 「約」や丸めを使う場合は、元の値の出典を同じ文に残す。
