# ADR(設計判断記録)の規律

対象: 代替案の比較や設計変更をするとき。判断理由を後から追えるようにする。

## 記録する場面
- 代替案の比較を始めたとき。
- 同じ問題に2回目のアプローチを考えたとき。

## 記録先と形式
`docs/adr/NNNN-短い題名.md` に、次の項目で書く。

- 状況: 何が問題か(事実・観測・推測を区別する)
- 決定: 採用した案
- 理由とトレードオフ: 採用の根拠と、失うもの
- 却下した選択肢: 各案と却下理由
- 影響: 変更が及ぶファイル・運用・費用・権限

費用・認証・権限に関わる案は、承認が必要であることを明記し、ADR 自体は承認の代わりにしない。
