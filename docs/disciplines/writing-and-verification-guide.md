# 文書執筆・検証記載の規律

対象: README、日英ガイド、Zenn記事、DEV記事、振り返りレポートなど、人が読む文書の執筆・更新。
このファイルは起動時に自動ロードされない。CLAUDE.md のトリガー表に当たったときに Read する。

## 手順

1. `_semantics/terminology-and-roles.md` と `_semantics/metrics-and-dates.md` を先に読む。
2. 書こうとする数値・ステータスの一次ソース(`baseline.json`、`docs/development-status-*.md`、試行レポート、CIログ)を開いて照合する。辞書と食い違えば一次ソースを正とし、辞書の修正を別途提案する。
3. 数値と検証結果には確認環境を添える: Pythonバージョン、コミットハッシュ、確認日。
4. 確認していない事項は「未確認」、解釈は「推測」と明記する。実行していない検証を「完了」「検証済み」と書かない。
5. 自分(AI)の関与範囲は、実際に行った作業だけを書く。
6. 日英版がある場合は両方を同じ内容に揃える。

## 書いたあとの確認

- 各数値に出典・日付・環境が付いているか。
- C1 / C2 v5 / C3 の表現が辞書の「書いてよい表現」に沿っているか。
- 履歴スナップショットの内容を現在の状態として書いていないか。
